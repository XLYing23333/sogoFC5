# FC4 4.2.1.145 amd64 接口边界

## 发行包组成

| 文件 | 角色与证据 |
| --- | --- |
| `fcitx-sogoupinyin.so` | Fcitx4 前端。导出 `ime`；导入 Fcitx4 的提交、预编辑、输入上下文等函数，同时引用 D-Bus、socket 和 XTest |
| `libSogouIme.so` | 原厂输入法编排与 UI 包装。保留大量 C++ 符号，可以为 Shell 接口提供调用点证据 |
| `libSogouShell.so` | 导出 `GetSogouShell`、`Release`、`GetSogouShellWrapper`；本工程主要分析 `GetSogouShell` 返回对象的接口 |
| `sogoupinyin-service` | 原厂服务、UI 与通信入口；嵌入与前端逐字节相同的请求和返回消息描述 |

`GetSogouShell` 与 `GetSogouShellWrapper` 是不同接口，不可混用对象指针或虚函数表。

## Shell 虚函数表

构造函数在 `libSogouShell.so` 的虚拟地址 `0x8a20f` 取得表地址 `0x9ec740`，再加 16 字节写入对象首地址。
实际可调用表起点为 `0x9ec750`。表中有 37 个连续可执行地址，紧随其后的指针为零。
地址只适用于 `vendor/baseline.json` 中指定哈希的 ELF；运行时还需要加 ELF 装载基址。

下表的名称由原厂调用者推断。C++ 声明表达已观察到的调用方式，不代表已经恢复原始头文件。
未确认的返回值、其他槽位和私有对象布局保持不透明。

| 字节偏移 | 调用 | 原厂调用点（`libSogouIme.so`） |
| --- | --- | --- |
| `0x20` | 路径初始化，五个字符串参数，调用方使用布尔返回值 | `0x481d00` |
| `0x28` | 激活输入布局，整数参数 | `0x2f78ce` |
| `0x30` | 输入字符，整数参数，布尔处理结果 | `0x2f7a4b` |
| `0x38` | 退格 | `0x2f7be9` |
| `0x40` | 清空组词 | `0x2f7dcd` |
| `0x48` | 选择候选，整数参数；调用方忽略返回值 | `0x2f7fbe` |
| `0x68`、`0x70` | 向后、向前翻页，布尔返回值 | `0x2f8170`、`0x2f81fd` |
| `0x80` | 候选列表接口 | `0x2f98ff` |
| `0x88` | 组词字符串接口 | `0x2fa052` |
| `0x98` | 提交结果字符串接口 | `0x2f9987` |
| `0xc8`、`0xd0` | 设置、读取组词游标 | `0x2f9215`、`0x2f9271` |
| `0xe0` | 整数状态查询 | `0x2f9368` |

字符串接口的第零槽返回 `const char*`；候选列表第零槽按索引返回字符串接口，第一槽读取数量。
这里只复制字符串内容，不跨库传递 `std::string` 或 `std::vector` 对象，也不释放原厂借用对象。
`ShellView` 最多复制 256 个候选、每个字符串小于 65536 字节。
这些边界不是内存损坏防护，也不保证闭源引擎调用会及时返回。

## 初始化约束

`GetSogouIme` 和 `GetSogouImeBase` 均调用 `0x2f6303` 的同一个创建函数。
因此 `GetSogouImeBase` 不能用作移除原厂 UI 的独立引擎入口。

原厂 `SogouShellWrapper::Init` 在 Shell 路径初始化前，调用 `GetSGAuthEnv` 并将环境传入 `0x10` 槽。
更上层的 `t_sogouIme::Init` 还执行授权环境初始化及资源检查。
这些行为不能因绕过 UI 包装而被默认为可省略。
`Vendor` 调用原厂 `t_stAuthEnv::Init(workspace, profile)` 和 `IsAuthValid` 后，将环境交给 Shell。
授权校验不通过时初始化失败，不修改原厂授权判断。

`0x20` 槽的两个主要路径沿原厂调用链对应系统词库和用户词库；其余路径的完整用途尚未确认。
`0x28` 激活操作还会选择语言布局并触发子引擎初始化。不能将路径初始化成功等同于可以开始输入。

## PC 布局和事件编码

原厂 `InputMode.xml` 的有效布局项将 `Keyboard_pcpy` 设为 `19`。
该布局的对象在 `0xa0b0e` 构造，虚函数表起点为 `0x9ecc10`。
其按键函数位于 `0xa175e`，从输入整数的最高位取得按下标志，从最低八位取得虚拟键码。
例如 `a` 的按下为 `0x80000041`，松开为 `0x00000041`。
ASCII `0x61` 不能用来表示 PC 布局的字母 A。

PC 引擎会使用 `t_keyboardManager::GetKeyboardState()` 返回的事件状态表完成字符转换。
这个已导出函数位于 `0x9e868`，返回对象内的 256 字节状态缓存；这里的读取函数不调用 X11 查询。
适配端通过该接口同步 Shift/Ctrl/Alt/Caps/Num，普通按键状态由原厂按下/松开逻辑管理。
这不等同于证明整个引擎没有其他 X11 调用。

PC 结果刷新函数 `0xa2ff8` 清空输出副本后，在 `0xa33d1` 调用内部状态对象第 25 槽，
再转换其返回的宽字符串，写入 PC 对象 `+0x48` 的 UTF-8 字符串。
根 Shell 的结果接口直接转发给 PC 子对象；清空 UTF-8 副本不能消费内部结果。
局部提交后继续组词、松键或翻页引起刷新时，该副本可能重新出现。

PC 子对象位于根对象 `+0x38`；PC 的 `+0x130` 保存内部状态接口，构造时的绑定见 `0xa0c65`。
内部状态虚函数表为 `0x9fc310`，第 25 槽 `0x410d3e` 返回当前上下文的借用结果缓冲。
该缓冲来自组词对象第 7 槽 `0x438f18`，即对象 `+0x1458`。
原厂瞬态清理函数 `0x4351f4` 通过同一槽取得指针，并在 `0x435217` 写入一个 32 位零字符。
适配端在每个操作开始前仅执行结果首字符清零，再通过原厂赋值函数 `0x7cd5c` 清空 UTF-8 副本。
不调用整个组词对象的重置；不清理剩余拼音、候选、其他瞬态字段或学习数据。
调用前核对库哈希、根 Shell、PC、内部状态和字符串对象的表地址；查询失败时终止当前工作进程的正常处理路径。

对应反汇编和接口表检查保存在 `abi/4.2.1.145/evidence` 和 `analysis.json`。
这证明指定二进制中的缓冲关系与写入方式；真实引擎在局部提交后的运行效果仍需桌面验证。
不会按字符串内容去重，因此不同操作主动提交相同汉字不会被合并。
UTF-8 赋值函数使用原厂自己的 `std::string` ABI，适配端不跨库构造或析构 C++ 字符串对象。

`libSogouShell.so` 本身链接 Qt5 Widgets/Gui/DBus、X11、Xtst 等库。
绕过 FC4 前端不能单独证明内部完全没有 UI 或全局键盘状态访问；必须继续核对实际调用路径。

PC 对象翻页入口 `0xa1b0e` 与 `0xa1b54` 分别调用内部对象 `0xa8` 与 `0xa0` 槽并刷新状态，之后固定返回 1。
因此根 Shell 的布尔翻页返回值不能证明存在上一页或下一页。
适配端只在候选内容实际变化时调整展示页码；完全相同的候选页在这个观测接口中无法区分。

## 小键盘数字与原生环境

X11 的 `KP_0` 至 `KP_9` 对应独立 PC 虚拟键 `0x60` 至 `0x69`。
PC 入口先执行 `ToAscii`，再由 `0xa0ad0` 将字符置于高 16 位、虚拟键置于低位，传给内部处理接口。
该字符/按键组合不能被主键区的 `0x30` 至 `0x39` 替代，否则会混入候选序号的语义。

`0x422af6` 返回当前输入状态使用的 `t_env`；其实现从状态对象 `+0x10` 获取或创建环境。
`BOOL_PadNumAsSelect` 为 `libSogouWbShell.so` 导出的环境条目指针。
小键盘候选选择路径在 `0x42623c` 读取该条目，关闭值会跳过相应选择分支。
适配端在激活后调用原生 `t_env::SetValueBool(entry, false)` 并回读，确保关闭小键盘选词。
该库的哈希也由 `vendor/baseline.json` 及运行时校验固定，赋值入口 `0x1ad098` 的参数已通过静态反汇编确认。
原厂正常环境保存可能写回这项策略；适配端不重写整个用户配置。

以上静态证据确认键盘身份、配置接口和选择分支；关闭选词后字母/数字混排的完整转换结果尚未通过真实引擎执行验证。
对应证据位于 `keypad-selection-gate.asm`、`native-input-environment.asm`、`native-key-character-packing.asm` 和 `native-bool-setting.asm`。

## Noble 加载边界

原厂库导入 `__cxa_throw_bad_array_new_length@Qt_5`，系统 Qt5 不提供该别名。
独立进程导出相同标准异常语义的兼容函数，抛出 `std::bad_array_new_length`。

`libSogouIme.so` 的 `n_sgxx::MainWindow` 虚函数表由原厂服务提供，大小为 512 字节。
独立进程为该重定位提供同大小的不可用占位对象，同时拦截该窗口的两个构造入口并立即终止自身。
这不是恢复的窗口实现：该进程不允许创建原厂窗口，也不提供可调用的原厂窗口虚函数表。
若引擎路径依赖这个窗口，将被视为不受支持并触发输入故障恢复，不能继续假定纯引擎路径可用。
原厂授权函数不在这些替换范围内。

包检查构造只用于加载器检查的共享对象，复现进程导出的兼容符号和整个原厂依赖组，使用 `ldd -r` 核对符号与版本重定位。
该检查不运行共享库构造函数、引擎初始化或中文转换。

## 协议定义

前端的描述信息位于文件偏移 `0x259d70`（请求，841 字节）和 `0x25a470`（返回，730 字节）。
服务端的对应描述信息与其逐字节一致，提取位置和描述哈希记录在 `abi/4.2.1.145/analysis.json`。

`szCompStr`、`nCursorIdx`、`nCursorPos` 描述组词和游标；`szCandResStr` 描述提交串；`strCands` 为候选列表。
消息中还存在模拟键、像素指针和窗口几何字段；它们是原厂协议字段，不代表 Fcitx5 接入必须实现这些行为。
恢复 `.proto` 用于确认信息分类和对照原厂调用，不要求复用原厂传输机制。

## 尚未验证的运行行为

- 已实现初始化序列在真实授权环境、资源路径和 PC 布局上的运行结果。
- 引擎字符串的实际编码、有效期及输出副本清理的运行效果。
- 字母、Shift 大写、标点、候选选择与处理结果之间的完整状态转换。
- 焦点变化时的组词边界，以及引擎对象是否允许独立上下文。
- 学习数据的保存、同步和退出清理。
- 原厂引擎在无 FC4、无 CPIS 的调用路径中的真实延迟与阻塞行为。

在这些边界明确前，ABI 合约测试通过不能作为完整输入法可用性的结论。
